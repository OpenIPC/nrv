# Десктоп-приложение

Приложение для рабочих мест операторов на Windows. Собирается
автоматически: готовый архив лежит во вкладке **Actions** на GitHub.

Общее описание и причины выбора технологии — в `docs/DESKTOP.md`.

## Что уже работает

- Вход с указанием адреса сервера, логина и пароля.
- Определение адреса веб-интерфейса (см. ниже) — вручную или автоматически.
- Запоминание адресов и логина между запусками.
- Токен хранится зашифрованным (привязан к учётной записи Windows).
- Список камер с состоянием: в сети или нет.
- Окно просмотра камеры для каждой камеры.
- Разговор через динамик камеры **без повторных запросов разрешения**.
- Перенос окна на другой монитор кнопкой в заголовке.
- Запоминание монитора и положения каждого окна.

## Два адреса: API и веб-интерфейс

Сервер отдаёт **два разных сервиса**:

| Что | Порт по умолчанию | Что отдаёт |
|---|---|---|
| **API** | 8080 | только данные: вход, список камер, события |
| **Веб-интерфейс** | 3001 | страницы, включая плеер и панель разговора |

Страницы существуют **только внутри веб-интерфейса** — это приложение на
React. Чистый API про пути вроде `/cameras/<id>` ничего не знает и
отвечает `404 page not found`.

### Частый случай: наружу проброшен один порт

Если на роутере открыт **только веб-интерфейс** (например, внешний
`83.243.73.86:8080` ведёт на внутренний `3001`), то всё работает через
этот единственный адрес. Веб-сервер интерфейса сам перенаправляет
`/api/` на бэкенд.

Приложение распознаёт этот случай: сначала проверяет, отдаёт ли
указанный адрес страницу входа, и если да — использует его для всего.

**Никакие дополнительные порты открывать не нужно.**

### Случай: API и интерфейс на разных портах

Если вы указали чистый адрес API (`192.168.1.111:8080`), адрес
интерфейса подбирается автоматически: проверяются порты 3001, 80,
8081, 8082 того же хоста. Признак интерфейса — успешный ответ на
`/login`.

Если подбор не сработал, укажите адрес вручную в поле
**«Адрес веб-интерфейса»** в окне входа.

### Про WebRTC и UDP

WebRTC даёт задержку меньше секунды, но требует **UDP-порт 8189**,
открытый до сервера. Через веб-прокси идёт только обмен описаниями,
а сам видеопоток идёт напрямую по UDP.

**Если UDP 8189 закрыт** (типичная ситуация при доступе через интернет),
WebRTC не установится — и приложение **автоматически откатится на HLS**.
Задержка вырастет до нескольких секунд, но просмотр будет работать.

Открывать UDP 8189 имеет смысл только для доступа изнутри локальной
сети. Для интернета это неудобно: провайдеры часто блокируют
произвольный UDP, а проброс создаёт лишнюю точку доступа.

## Как получить готовое приложение

1. Откройте репозиторий на GitHub.
2. Перейдите во вкладку **Actions**.
3. Выберите слева **Сборка десктоп-приложения**.
4. Откройте последний запуск (зелёная галочка).
5. Скачайте **NvrDesktop-win-x64** внизу страницы.

Распакуйте архив и запустите `NvrDesktop.exe`. Устанавливать ничего не
нужно: .NET и всё остальное уже внутри.

## Сборка вручную

Нужна машина с Windows и .NET 8 SDK. WPF не собирается на Linux.

```
cd desktop
dotnet publish src/NvrDesktop/NvrDesktop.csproj -c Release -r win-x64 --self-contained true -o ./publish
```

Готовый файл: `desktop/publish/NvrDesktop.exe`.

## Требования

- **Windows 10 или 11.**
- **WebView2 Runtime.** В Windows 11 он уже установлен. Для Windows 10
  скачайте «Evergreen Standalone Installer» с сайта Microsoft —
  он ставится один раз и не требует прав администратора.

Без WebView2 приложение запустится и покажет понятное сообщение о том,
чего не хватает, — окно камеры просто не откроется.

## Настройки и данные

Всё лежит в профиле пользователя:

```
%APPDATA%\NvrDesktop\settings.json   — адреса, логин, положение окон
%APPDATA%\NvrDesktop\token.bin       — токен доступа (зашифрован)
%LOCALAPPDATA%\NvrDesktop\WebView2\  — кэш встроенного браузера
```

В `settings.json` два адреса: `ServerUrl` (API) и `UiUrl` (интерфейс).
Второй заполняется автоматически после первого входа.

Пароль нигде не сохраняется. Токен зашифрован и привязан к учётной
записи: скопировать файл на другую машину и войти с него нельзя.

## Как это устроено

Оболочка на C# (WPF) плюс встроенный браузер (WebView2) с обычным
веб-интерфейсом внутри. Плеер, архив, события и панель разговора —
это существующие страницы, они не переписывались.

Оболочка берёт на себя то, чего браузер не даёт: окна на нескольких
мониторах, защищённое хранение токена и разрешения без повторных
подтверждений.

```
src/NvrDesktop/
├── App.xaml, App.xaml.cs           — запуск, вход по сохранённому токену
├── Services/
│   ├── ApiClient.cs                — запросы к API, подбор адреса интерфейса
│   ├── TokenStore.cs               — шифрованное хранение токена
│   └── SettingsStore.cs            — настройки и положение окон
└── Windows/
    ├── LoginWindow.xaml            — вход: адреса, логин, пароль
    ├── MainWindow.xaml             — список камер
    ├── CameraWindow.xaml           — просмотр камеры
    └── WindowManager.cs            — мониторы и запоминание положения
```
