# Настройка точности детекции

Практическое руководство: как убрать ложные срабатывания, не потеряв реальные
объекты. Все параметры меняются в карточке камеры, вкладка **Детекция**.

---

## Как устроена фильтрация

Кадр проходит три уровня проверок, прежде чем превратиться в событие:

```
Кадр с камеры
   │
   ├─ 1. Порог инференса модели (CONFIDENCE, 0.25)
   │     Отсекает самые слабые находки ещё до фильтров.
   │
   ├─ 2. Порог уверенности камеры (min_confidence)
   │     Настраивается для каждой камеры отдельно.
   │
   ├─ 3. Фильтры формы и размера
   │     • минимальная площадь объекта
   │     • максимальная площадь объекта
   │     • отношение сторон рамки
   │     • неподвижность
   │
   └─ Событие
```

Порядок важен: **поднятие порога уверенности — не единственный способ** убрать
шум, и часто не лучший. Фильтры по размеру и форме отсекают ложные рамки,
не затрагивая реальные объекты.

---

## Что было не так на реальной системе

Замеры до настройки, за сутки:

| Класс | Событий | Проблема |
|---|---|---|
| `face` | 475 | Больше, чем людей (104) — распознавание шло на каждом кадре |
| `cat` | 278 | Коты детектировались там, где их нет |
| `person` | 95 | Реальная цель |
| `dog` | 77 | |
| `car` | 55 | |

Три причины:

1. **Распознавание лиц не требовало человека в кадре.** Модель находила «лица»
   в текстурах, отражениях и бликах. Отсюда 475 событий при 104 событиях по людям.

2. **Порог уверенности 0.4** стоял у 14 из 19 камер. Для YOLOv8 это низко:
   через такой порог проходит шум.

3. **Не проверялся размер объекта.** Ложная рамка 20×20 пикселей проходила
   наравне с человеком в полный рост.

---

## Главный подвох: распределение уверенности

Замер на живой системе показал, что **большинство объектов имеет уверенность
0.40–0.60**:

| Уверенность | Событий | Доля |
|---|---|---|
| 0.40–0.50 | 154 | 48% |
| 0.50–0.60 | 122 | 38% |
| 0.60–0.70 | 19 | 6% |
| выше 0.70 | 23 | 7% |

> **Важно.** Порог 0.6 отсекает **86% событий**. На тестовой камере после
> такого подъёма за 5 минут не прошло ни одного объекта, хотя реальные цели
> в кадре были.

Поэтому порог по умолчанию — **0.5**, а не 0.6. Основную работу по очистке
от шума делают фильтры размера и формы, а не порог уверенности.

---

## Параметры

### Порог уверенности (`min_confidence`)

Значение по умолчанию — **0.5**.

| Значение | Когда ставить |
|---|---|
| 0.3–0.4 | Только если нужно ловить объекты в темноте или вдали, а шум терпим |
| **0.5** | Рабочее значение для большинства камер |
| 0.7–0.9 | Когда важнее чистота событий, чем полнота (например, триггер на открытие двери) |

### Минимальная площадь объекта (`min_object_area`)

Значение по умолчанию — **0.004** (0,4% площади кадра).

Ориентиры для кадра субпотока 704×576:

| Объект | Площадь рамки | Проходит при 0.4%? |
|---|---|---|
| Человек вблизи | ~20% | да |
| Человек вдали | ~1,7% | да |
| Кошка средних размеров | ~1,3% | да |
| Шум, блик | меньше 0,3% | нет |

Как подбирать: посмотрите события камеры за сутки, найдите ложные, оцените
их размер на снимке. Если ложные рамки крупные (предмет обстановки), поднимите
значение до 1–2%. Если пропускаются нужные объекты — снижайте.

> **Осторожно с порогом 2%.** Замер показал, что человек вдали занимает 1,7%
> кадра и при пороге 2% **отсекается**. Значение выше 1% подходит только для
> камер, где цель всегда крупная.

### Максимальное отношение сторон (`max_aspect_ratio`)

Значение по умолчанию — **5.0** (5:1).

Отсекает вытянутые рамки, которые YOLO ставит на тени, столбы, отражения
и щели. Человек укладывается в 2:1, машина — в 3:1. Значение `0` выключает
проверку.

### Неподвижность (`static_seconds`)

Значение по умолчанию — **0** (выключено).

Объект, который стоит на месте дольше указанного времени, перестаёт давать
события. Полезно для камер в помещении, где в кадр попадают стулья, коробки
и предметы обстановки. Разумные значения — 60–300 секунд.

> Не включайте на камерах, где объекты могут долго оставаться на месте по
> делу: припаркованная машина, человек на посту.

### Распознавание лиц

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| `face_requires_person` | **включено** | Искать лица только когда в кадре уверенно найден человек |
| `face_min_confidence` | **0.5** | Какая уверенность человека нужна для запуска поиска лиц |

Первый параметр — основной. Без него распознавание запускается на каждом
кадре, и модель находит лица в текстурах. На реальной системе это давало
в пять раз больше событий по лицам, чем по людям.

Выключать стоит только для камер, где лица нужно искать без людей в кадре —
например, при распознавании по фотографии на пропуске.

---

## Порядок настройки

1. **Уберите лишние классы.** Если кошка у ворот — не сигнал тревоги, снимите
   галочку `cat` в списке классов. Это надёжнее любых порогов.

2. **Оставьте порог 0.5.** Для большинства камер менять его не нужно.

3. **Проверьте список событий за сутки.** Если много ложных — посмотрите на
   снимки: какого размера рамка?

4. **Настройте минимальную площадь.** Если ложные рамки мелкие — поднимайте
   до 0,5–1%. Если пропадают реальные объекты — снижайте до 0,2–0,3%.

5. **Включите отсечение неподвижных**, если в кадре есть мебель или предметы,
   которые детектор принимает за объекты.

6. **Проверьте пребуфер.** Если в записи события не видно самого объекта —
   увеличьте `prebuffer_sec` в настройках записи (см. ниже).

---

## Объект не попадает в запись

### Причина

Клип собирается от момента события, а запись часто стартует **в этот же
момент** — пребуфера ещё нет. В клип попадает только время после события,
а объект уже вышел из кадра.

Замер показал разрыв: события приходили за **7–15 секунд** до начала клипа.

### Что сделано

Сборка клипа теперь проверяет, набран ли пребуфер. Если запись началась
позже события, клип не собирается, а в лог пишется:

```
клип пропущен: пребуфер не набран: запись идёт с 10:20:53, а событие было
в 10:20:38 (нужно 15 с) — увеличьте пребуфер в настройках камеры
```

Пропуск клипа честнее, чем клип без объекта: запись без цели только занимает
место в архиве.

### Настройка

| Параметр | Значение по умолчанию | Что делать |
|---|---|---|
| `prebuffer_sec` | 10 | Увеличить до **15–20**: детекция приходит с задержкой |
| `postbuffer_sec` | 20 | Оставить: объект обычно уходит через 10–20 секунд |

Задержка детекции складывается из интервала публикации кадров и времени
инференса. На камерах с большим числом объектов она больше.

---

## Если событий стало слишком мало

Проверьте по порядку:

1. **Порог уверенности** — не поднят ли выше 0.5. Это самая частая причина.
2. **Минимальная площадь** — не стоит ли 2%. Человек вдали отсекается.
3. **Список классов** — есть ли нужный класс в списке.
4. **Зона детекции** — попадает ли цель в нарисованный полигон.
5. **Неподвижность** — не включено ли отсечение при долгом стоянии объекта.

Посмотреть, что видит модель, можно в логе детектора:

```bash
docker compose logs ai-detector --since 5m | grep "объектов"
```

Строка вида `2 объектов ['person', 'car'] за 31 мс` означает, что объекты
найдены и прошли фильтры.

## Распознавание автомобильных номеров

### Как устроено

Для камер с включённым распознаванием номеров работает **отдельный быстрый
поток кадров**:

| | Обычный поток | Поток номеров |
|---|---|---|
| Частота | 1 кадр/с | **5 кадров/с** |
| Что в кадре | весь кадр камеры | **только зона поиска номера** |
| Что ищется | объекты, лица, номера | **только номера** |
| Ширина кадра | 960 | 640 |

Причина разделения: машина проезжает зону за 2–3 секунды, а кадры идут раз
в секунду — шанс поймать её в кадре невелик. На быстром потоке машина
попадает в кадр гарантированно, а кадрирование по зоне делает номер крупнее
и читаемее.

> **Обязательно нарисуйте зону поиска номера.** Без неё быстрый поток не
> запускается: кадрировать нечего. Зона рисуется мышью в карточке камеры,
> вкладка **Детекция**, блок «Распознавание номеров».

Кадры публикуются в отдельную тему `cameras.<id>.plate_frame`. Детектор
обрабатывает их только распознаванием номеров — детекция объектов для них
не запускается, поэтому нагрузка растёт умеренно.

### Почему поток непрерывный, а не по кадру

Первая версия брала одиночные кадры командой `ffmpeg -frames:v 1`. Замер
показал **1,5 секунды на кадр** — почти всё время уходит на подключение к
RTSP (рукопожатие, выбор профиля, буферизация). Вместо пяти кадров в секунду
получалось **0,7**.

Теперь ffmpeg подключается **один раз** и пишет кадры подряд в трубу
(класс `FFmpegStream`), а приложение читает их потоком. Замер на тех же
камерах:

| Способ | Кадров в секунду |
|---|---|
| Одиночные кадры | 0,7 |
| Непрерывный поток | **15** (по 5 на камеру) |

Разница в 20 раз. Для распознавания номеров это решающе: при 0,7 кадра в
секунду машина успевала проехать между кадрами.

### Что отсекается

Распознавание номеров борется с мусором на четырёх уровнях:

**1. Служебные символы OCR.** Tesseract часто добавляет к номеру дефисы,
точки и кавычки. Раньше из-за этого верно прочитанный номер не проходил
проверку формата и событие терялось:

```
A-123-BC-77  →  A123BC77  →  проходит
```

**2. Полоса OSD внизу кадра.** Камеры рисуют поверх картинки дату, имя
модели и служебные сообщения — на OpenIPC это нижние 10–15% высоты.
OCR читал их как номер:

| Что в кадре | Что читал OCR | Сейчас |
|---|---|---|
| `Нет лицензии` | `COMOTO`, `YMOO` | отсекается |
| `domofon` | `DOMOFON`, `MOTOM` | отсекается |
| `OpenIPC` | `OPENIPC` | отсекается |

Нижняя полоса кадра (18% высоты) исключается из поиска номеров целиком:
подпись рисуется поверх изображения в самом низу, и номер физически не
может оказаться с ней на одной высоте.

**3. Структура строки.** Слово и номер различаются чередованием гласных и
длиной цепочек согласных. Плюс отдельный список известных надписей камер.

**4. Шаблон формата.** Если задан `plate_pattern`, номер проверяется по нему.
Для российских номеров подходит шаблон из предустановки `ru`:

```
^[ABEKMHOPCTYX]\d{3}[ABEKMHOPCTYX]{2}\d{2,3}$
```

### Настройка

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| `plate_zone` | пусто | **Зона поиска. Без неё быстрый поток не работает** |
| `plate_pattern` | пусто | Шаблон номера. Пусто — проверяется только длина |
| `plate_min_length` / `plate_max_length` | 8 / 12 | Допустимая длина |
| `plate_min_confidence` | 0.3 | Порог уверенности OCR |

Переменные окружения `frame-publisher`:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PLATE_FRAME_INTERVAL` | 0.2 | Интервал кадров зоны в секундах |
| `PLATE_FRAME_WIDTH` | 640 | Ширина кадра зоны |

### Если номера не распознаются

1. **Проверьте зону.** Убедитесь, что она накрывает дорогу, а не только
   часть кадра. В логе должно быть:
   ```
   [xxxxxxxx] Камера ...: быстрый поток номеров запущен (0.2 с)
   ```
   Если вместо этого `зона номеров не задана` — зона не нарисована.

2. **Проверьте шаблон.** Если он задан слишком строго, верные номера
   отклоняются. Посмотрите в логе отклонения:
   ```bash
   docker compose logs ai-detector --since 10m | grep "номер отклонён"
   ```

3. **Проверьте, видно ли номер в кадре.** Убедитесь, что камера стоит так,
   что номер читается: не слишком далеко, не под острым углом, кадр не смазан.

4. **Проверьте порог OCR.** Значение 0.3 подходит для большинства случаев.
   При плохом освещении можно снизить до 0.2.

### Ограничения

- **Номера распознаются только на кадрах детекции.** Если машина проехала
  мимо и не попала ни в один кадр, события не будет. Быстрый поток снижает
  вероятность пропуска, но не исключает его полностью.
- **Скорость чтения.** На кадре 640 пикселей номер занимает 100–150
  пикселей: этого достаточно для чтения, но при сильном смазывании OCR
  может ошибиться в отдельных символах.
- **Ночью.** Без инфракрасной подсветки номер не читается. При ИК-подсветке
  светлые цифры на тёмном фоне читаются хуже, чем днём.

## Проверка изменений

```bash
# События за последние 5 минут по классам
docker exec gigacode-postgres-1 psql -U nvr -d nvr -c "
SELECT object_class, count(*), round(avg(confidence)::numeric,2) AS средняя
FROM detection_events WHERE timestamp > now() - interval '5 minutes'
GROUP BY object_class ORDER BY 2 DESC;"

# Какие пороги стоят на камерах
docker exec gigacode-postgres-1 psql -U nvr -d nvr -c "
SELECT c.name, d.min_confidence, d.min_object_area, d.object_classes
FROM detection_settings d JOIN cameras c ON c.id = d.camera_id
WHERE d.enabled ORDER BY c.name;"
```

Изменения настроек детектор подхватывает за 10 секунд — перезапуск не нужен.
