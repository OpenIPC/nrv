# Внешний RTSP-доступ

Выдача потоков камер сторонним системам: видеостенам, регистраторам,
сторонней аналитике. Внешние потребители берут поток у NVR, а не
подключаются к камерам напрямую.

---

## Зачем это нужно

Камеры OpenIPC слабые и ограничивают число одновременных RTSP-сессий.
При исчерпании лимита камера отвечает отказом:

```
method SETUP failed: 453 Live memory budget is full
```

Это не сбой сети, а защита устройства: кончилась память под сессии.
Если каждая внешняя система подключается к камере напрямую, лимит
выбирается почти сразу, и поток пропадает у всех — включая запись архива.

```
Было:  камера ──┬── NVR (запись)
                ├── видеостена №1        ← отдельная сессия на каждую систему
                └── видеостена №2        ← лимит 2–3 сессии, дальше отказ

Стало: камера ──► go2rtc ──┬── NVR (запись)
                             ├── видеостена №1
                             └── видеостена №2
```

Подключение к камере остаётся **одно**. Дальше поток раздаётся копией,
сколько бы потребителей ни подключилось.

---

## Адреса потоков

```
rtsp://ЛОГИН:ПАРОЛЬ@АДРЕС_СЕРВЕРА:9784/cameras/{N}/streaming/main
rtsp://ЛОГИН:ПАРОЛЬ@АДРЕС_СЕРВЕРА:9784/cameras/{N}/streaming/sub
```

| Часть | Значение |
|---|---|
| `9784` | Порт для внешних систем. Внутренний RTSP-порт go2rtc остаётся `8554` |
| `{N}` | **Номер канала со смещением на минус один**: канал 1 → `0`, канал 5 → `4` |
| `main` | Основной поток: полное разрешение камеры, для записи и детального просмотра |
| `sub` | Дополнительный поток: лёгкий, для сетки и постоянного просмотра |

### Смещение на минус один

Нумерация в адресе начинается с нуля, как принято в большинстве
видеосистем. Канал, указанный в карточке камеры, и индекс в адресе
различаются на единицу:

| Канал в интерфейсе | Адрес |
|---|---|
| 1 | `/cameras/0/streaming/main` |
| 2 | `/cameras/1/streaming/main` |
| 5 | `/cameras/4/streaming/main` |

Перепутать легко, поэтому на странице **Внешний доступ** показаны оба
значения сразу, а в ссылках уже подставлен нужный индекс — их можно
скопировать кнопкой.

## Принцип вывода OSD

В проксированном потоке метка времени, имя камеры и другие надписи **уже
присутствуют в видео**. NVR их не накладывает и не изменяет.

Причина: на камерах OpenIPC OSD встраивается в поток самой прошивкой
(Majestic) ещё до отправки по сети. Камера рисует надпись в кадре
аппаратно, средствами сенсора и энкодера, а NVR получает уже готовое
изображение с наложенным текстом.

```
Камера: сенсор → OSD (аппаратно) → энкодер H.264 → RTSP
                                                      │
NVR:                                    go2rtc ─────┘  ← OSD уже в кадре
                                            │
                            ┌───────────────┼───────────────┐
                        запись           браузер      внешние системы
                     (OSD в кадре)    (OSD в кадре)   (OSD в кадре)
```

**Практический вывод:** надпись одинакова для всех потребителей. Если
изменить текст или положение OSD, это увидят и архив, и браузер, и
внешние системы — потому что источник один.

### Настройки OSD

Задаются в карточке камеры на вкладке **Настройки** (через API прошивки,
без SSH) или в веб-интерфейсе самой камеры:

| Параметр | Что делает |
|---|---|
| `osd.enabled` | Общий выключатель надписей на камере |
| `osd.template` | Текст с подстановками: `%d.%m.%Y %H:%M:%S` — дата и время |
| `osd.size`, `osd.posX`, `osd.posY` | Размер и положение надписи |
| `osd.bgAlpha`, `osd.outline` | Фон и обводка — читаемость на светлом фоне |
| `osd.overlays` | Дополнительные надписи (вторая и третья строки) |

Отдельные флаги управляют тем, в какие именно потоки встраивается OSD:

| Флаг | Поток |
|---|---|
| `video0.osd` | Основной поток (`/streaming/main`) |
| `video1.osd` | Дополнительный поток (`/streaming/sub`) |
| `jpeg.osd` | Кадр превью (`/image.jpg`) |

Флаги независимы. Например, можно оставить OSD в основном потоке для
архива, но убрать из дополнительного — если он идёт на видеостену,
где подписи рисует сама видеостена и они дублировались бы.

### Точное время

Время в OSD берётся с часов камеры, а не сервера. Если часы камеры
сбиты, надпись на видео будет расходиться с метками событий и записей
в архиве.

Проверить часы камеры можно через API прошивки:

```bash
curl -u root:ПАРОЛЬ http://АДРЕС_КАМЕРЫ/cgi-bin/j/pulse.cgi
```

## Настройка

### 1. Учётные данные

Задаются переменными окружения при запуске. Значения по умолчанию —
`viewer` / `viewer`, **смените их перед выводом системы в сеть**:

```bash
# .env рядом с docker-compose.yml
EXTERNAL_RTSP_USER=nvr_viewer
EXTERNAL_RTSP_PASS=надёжный_пароль
```

```bash
docker compose up -d go2rtc backend
```

Эти же значения compose передаёт в go2rtc (`RTSP_EXTERNAL_USER` /
`RTSP_EXTERNAL_PASS`) — пароль проверяет сам медиасервер.

Внешнему пользователю разрешено **только чтение**: публиковать в наши
потоки и менять конфигурацию сервера он не может.

Внутренние потребители (бэкенд, детектор, архив) пароля не видят: go2rtc
отключает проверку для адресов localhost. Детектор живёт в bridge-сети,
поэтому ему адрес передаётся вместе с данными (`GO2RTC_RTSP` в
`docker-compose.yml`).

### 2. Номера каналов

Номер назначается автоматически при добавлении камеры — подставляется
наименьший свободный. Изменить или снять номер можно:

- в карточке камеры: поле **Номер канала**;
- на странице **Внешний доступ**: блок для камер без номера.

Номер уникален. Попытка занять занятый номер отклоняется с пояснением,
какой канал его уже использует.

### 3. Проверка

Страница **Внешний доступ** показывает параметры подключения и готовые
ссылки по каждому каналу. Проверить поток из командной строки:

```bash
ffprobe -rtsp_transport tcp \
  "rtsp://viewer:viewer@АДРЕС_СЕРВЕРА:9784/cameras/0/streaming/main"
```

Ожидаемый вывод — строка с кодеком и разрешением:

```
Stream #0:0: Video: h264, yuv420p, 1920x1080
```

## Поведение и ограничения

### Камера не в сети

Поток в go2rtc зарегистрирован, но подключиться к камере не удаётся —
поэтому RTSP отвечает `404 Not Found`. Это отличается от неверного номера
канала, который тоже даёт `404`. Различить их можно на странице
**Внешний доступ**: у офлайн-канала видна пометка «камера не в сети».

### Что видит внешняя система в кадре

Ровно то, что отдаёт камера: её разрешение, кодек и **OSD, встроенный
камерой**. Перекодирования нет, поэтому качество и задержка такие же,
как при прямом подключении к камере.

Если требуется разный OSD для разных потребителей, единственный способ —
добавить второй поток на самой камере с другими настройками подписей.

### Изменение настроек камеры

Внешние потоки читают внутренние потоки go2rtc. Правка адреса потока
или учётных данных камеры автоматически пересоздаёт потоки — внешним
системам ничего перенастраивать не нужно, адрес остаётся прежним.

### Смена номера канала

Старый адрес освобождается, новый создаётся. Внешней системе, которая
продолжает запрашивать прежний номер, придёт `404` — это ожидаемо,
номер нужно обновить на её стороне.

## Устройство

| Компонент | Роль |
|---|---|
| `backend/internal/service/external_rtsp_service.go` | Публикация потоков в go2rtc, учётные данные, список каналов |
| `backend/internal/api/handlers/external_rtsp.go` | API: настройки и быстрое назначение номера |
| `rtsp-proxy/nginx.conf` | Порт 9784: передача RTSP-трафика в go2rtc |
| `go2rtc/go2rtc.example.yaml` | Пароль RTSP-сервера (`rtsp.username`/`rtsp.password`) |
| `backend/migrations/010_camera_channel_number.*.sql` | Поле номера канала |

### Почему отдельный nginx

У go2rtc один RTSP-порт, и пароль в нём задаётся для всех, кроме
localhost. Внутренние потребители ходят по `127.0.0.1` (где проверка не
работает), а внешние системы — через отдельный порт: nginx слушает `9784`
и передаёт поток в go2rtc, не разбирая протокол. Заголовок
`Authorization` от внешнего клиента доходит до go2rtc как есть, и пароль
проверяет сам медиасервер.

### API

| Метод | Назначение |
|---|---|
| `GET /api/v1/rtsp/settings` | Параметры подключения, каналы, камеры без номера |
| `POST /api/v1/rtsp/channels/{cameraId}` | Назначить номер канала |

## Диагностика

| Симптом | Причина | Решение |
|---|---|---|
| `401 Unauthorized` | Неверные учётные данные | Проверить `EXTERNAL_RTSP_USER` / `EXTERNAL_RTSP_PASS`, перезапустить `go2rtc` и `backend` |
| `404 Not Found` | Камера офлайн **или** неверный номер канала | Открыть страницу **Внешний доступ**: у офлайн-канала есть пометка, номер сверяется по таблице |
| Поток есть, но чёрный кадр | Камера отдаёт поток, но изображение не формируется | Проверить камеру в её веб-интерфейсе, посмотреть раздел **Здоровье** в карточке камеры |
| `453` в логах камеры или go2rtc | Исчерпан лимит RTSP-сессий камеры | Проверить, не подключился ли кто-то к камере напрямую, минуя NVR |
| Пути исчезают сами | Монитор статуса удаляет «висячие» пути | Внешние адреса исключены из очистки; если пропадают — смотреть логи бэкенда |

Логи go2rtc и бэкенда:

```bash
docker compose logs -f go2rtc
docker compose logs -f backend | grep -i "внешн\|опубликов"
```
