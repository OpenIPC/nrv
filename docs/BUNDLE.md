# Комплект поставки (установка без интернета)

Комплект — это каталог со всем, что нужно установщику на объекте, где интернета
нет: образы Docker, пакеты системы, веса моделей распознавания и исходники.
Собирается один раз на машине с интернетом (в офисе), уезжает на флешке.

## Сборка комплекта

Собирать нужно на той же системе, что и целевая (пакеты apt берутся под неё):

```bash
sudo ./scripts/make-bundle.sh --out /srv/nvr-bundle
```

Что получится:

```
/srv/nvr-bundle/
  src/          исходники сервера (то, что проверено здесь)
  images/       образы Docker в tar (zstd) — грузятся без скачивания
  apt/          локальный репозиторий apt: Docker, chrony, whiptail, python3
  nvidia/       пакеты nvidia-container-toolkit (с --with-nvidia)
  models/       веса моделей, снятые с работающего детектора
  version.txt   версия, дата, система сборки, коммит
  SHA256SUMS    контрольные суммы — проверка, что флешка не побилась
```

Полезные параметры: `--with-sip` (домофония), `--with-minio`, `--with-nvidia`
(пакеты для видеокарты), `--skip-build` (не пересобирать образы, взять готовые),
`--skip-models`.

Проверка комплекта после перевозки:

```bash
cd /srv/nvr-bundle && sha256sum -c SHA256SUMS
```

## Установка на объекте

```bash
cd /root/nvr-bundle/src
sudo ./install.sh --bundle=/root/nvr-bundle --answers=/root/nvr-answers.conf
```

Или мастером (он спрашивает то же самое, что и обычно, но без вопросов, если
дан файл ответов):

```bash
sudo ./scripts/nvr-install.sh --bundle=/root/nvr-bundle --answers=/root/nvr-answers.conf
```

Что меняется по сравнению с установкой по сети:

| Шаг | По сети | Из комплекта |
|---|---|---|
| Исходники | скачиваются с `UPDATE_REPO_URL` | раскладываются из `src/` |
| Пакеты apt | из зеркал дистрибутива | из локального репозитория `apt/` |
| Образы Docker | собираются (нужны pip и npm) | загружаются из `images/` |
| Пакеты NVIDIA | из репозитория NVIDIA | из `nvidia/` |
| Веса моделей | детектор качает сам | распаковываются в тома из `models/` |

Сборка образов в режиме комплекта не выполняется намеренно: внутри образов
работают `pip` и `npm`, которым нужна сеть.

## Комплект внутри ISO

Собранный комплект можно вложить прямо в установочный образ — тогда на объект
едет один носитель, и после установки системы мастер запускается без вопросов:

```bash
sudo ./scripts/make-iso.sh \
    --base /путь/debian-12.13.0-amd64-netinst.iso \
    --answers /root/nvr-answers.conf \
    --bundle /srv/nvr-bundle \
    --root-key /root/.ssh/id_ed25519.pub \
    --out /var/lib/vz/template/iso/nvr-auto.iso
```

После установки на машине окажутся: `/root/nvr` (исходники), `/root/nvr-bundle`
(комплект) и `/root/nvr-answers.conf` (ответы, уже со ссылкой на комплект).

Ограничение: ISO9660 не принимает файлы больше 4 ГБ. Для сборки без видеокарты
это не мешает (сжатый образ детектора — около 1,5 ГБ), а комплект с CUDA-образом
(около 18 ГБ) в один слой не влезет — его везут отдельной флешкой.

## Почему модели снимаются с работающего детектора

Детектор скачивает веса сам, из разных мест (insightface, HuggingFace,
fast-plate-ocr), и часть ссылок со временем меняется. Поэтому сборщик поднимает
детектор с интернетом, ждёт сообщения «распознавание лиц включено» в его журнале
и снимает слепок готовых каталогов. На объекте распаковывается ровно то, что
проверено в офисе.

## Что стоит помнить

- **Размер.** Комплект с процессорной детекцией — единицы гигабайт; большая
  часть — образ детектора. Для сравнения: образ с CUDA около 18 ГБ.
- **Система сборки.** Пакеты apt собираются под ту систему, где запущен сборщик.
  Она записана в `version.txt` — по ней видно, годится ли комплект для объекта.
- **Пароли.** В комплект попадает чистое дерево исходников без `.env`: при
  установке на объекте пароли генерируются свои. Проверить, что в комплекте нет
  файла `.env`, стоит перед выездом.
- **Обновление объекта.** Обновление закрытого объекта с флешки — отдельный
  этап (Э4 в `plans/offline-iso-install.md`): комплект обновляется тем же
  сборщиком, а на объекте применяется через существующий механизм обновлений.
